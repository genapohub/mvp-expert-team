# 记忆轮转归档规则（mvp-expert-team 专用）

> 本文件定义 mvp-expert-team 执行期间的记忆生命周期管理算法。
> 结构对齐 01-Skills 技能体系通用的 `.skills-memory/` 方案；本技能独立使用时同样适用，无任何外部依赖。

## 零、确定项目根路径（所有工具必须执行）

`.skills-memory/` 是**项目级**目录，创建在**交付项目根目录**下，不是技能所在目录。

不同工具的 CWD 行为不同，读写 `.skills-memory/` 之前必须先确定项目根：

**Step 0.1 检测工具类型**
- 检查 SKILL.md 的加载路径：
  - `~/.workbuddy/skills/` → WorkBuddy
  - `~/.codex/skills/` → Codex
  - `~/.zcode/skills/` → ZCode
  - `~/.cursor/skills-cursor/` → Cursor
  - 其他路径 → Trae / 未知工具

**Step 0.2 确定项目根（按优先级）**
1. WorkBuddy：`$PWD` 或当前对话工作空间路径 → 直接用
2. Codex / Cursor / Trae：`pwd` 后若明显非项目根（如 `~/`、工具目录），向上找最近的 `.git` 以其父目录为项目根
3. 找不到 `.git` → 找 `package.json` / `pyproject.toml` / `go.mod` 等标志文件
4. 均失败 → 询问用户「当前项目根目录是什么？」
5. 确定为 `${PROJECT_ROOT}`，后续所有 `.skills-memory/` 路径基于此根

**Step 0.3 验证**
- 首次写入前先 `mkdir -p ${PROJECT_ROOT}/.skills-memory/`
- 成功 → 继续；失败 → 报错并告知用户手动创建

### 路径统一写法
- 读：`${PROJECT_ROOT}/.skills-memory/MEMORY.md`
- 写：`${PROJECT_ROOT}/.skills-memory/YYYY-MM-DD.md`

## 一、目录结构

```
.skills-memory/
├── MEMORY.md              # 热记忆：可复用决策、项目约定（按 ## 技能名分段）
├── project-tracker.md     # 项目进度台账（ledger）：任务级进度/阶段里程碑/关键裁决 Ruling
├── YYYY-MM-DD.md          # 活跃日志：近 30 天每日记录（追加模式）
└── archive/               # 冷归档
    ├── YYYY-MM.md         # 月度日报摘要（12 篇/年）
    └── legacy-memory-{YYYY}.md  # MEMORY.md 历史存档溢出（年度）
```

> **project-tracker.md 说明**：
> - MEMORY.md 存**可复用决策**，project-tracker.md 存**进行中项目的任务级进度**，两者解耦。
> - 由项目总监维护（每 Phase 更新）；角色不写本文件。
> - 会话丢失后，执行前先读 project-tracker.md 恢复项目状态再定位中断位置。
> - 格式：`## {项目名}（日期 → 状态）` 段下追加 `[日期] Phase/角色 完成：摘要`、`[日期] 裁决（Ruling）：决定—理由—代价`、`[日期] 阻塞：问题+状态`。
> - 轮转：project-tracker.md 不参与 30 天归档，随项目生命周期长期保留；项目结束后段首标注 `[已结项]`。

## 二、写入格式

### 每日日志（YYYY-MM-DD.md）

每条格式：`[mvp-expert-team] 场景描述 → 关键决策`

- 一行一个条目；同一天多条按 Phase 分组。
- 全流程交付时：每个 Phase 完成后各追加一条，最后总监追加交付汇总条目。
- 单 Phase 咨询（只用技能一部分能力）也须记一条。

### 长期记忆（MEMORY.md）

- 按 `## mvp-expert-team` 分段（或在用户已有分段体系中追加同名分段）。
- 每条 1-2 行；写入前检查同分段是否已有语义相近条目，有则更新而非追加（去重）。

### 轮转分工

| 使用场景 | 写日志 | 轮转归档 |
|---------|--------|---------|
| mvp-expert-team 独立执行 | ✅ 总监统一写 | ✅ 总监统一做 |
| 被外部调度器（如 orchestrator）调度 | ❌ 由调度器统一处理 | ❌ 由调度器统一做 |

---

## 三、轮转参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 年龄阈值 | 30 天 | 日报超此年龄 → 触发归档 |
| 数量硬上限 | 35 篇 | 防止阈值长期不触发导致的堆积 |
| 归档粒度 | 月度 `archive/YYYY-MM.md` | 保留每日 1-3 行摘要，压缩约 95% |
| MEMORY.md 自清理 | 超 500 行 | 超 6 个月未更新的条目移至 `## 历史存档` 尾段 |
| 历史存档溢出 | `## 历史存档` 超 200 行 | 整体迁移到 `archive/legacy-memory-{YYYY}.md` |

---

## 四、触发条件

每次写入日志后轻量检查，满足任一即触发完整轮转：
- 条件 A：存在日报日期早于「今天 − 30 天」
- 条件 B：日报文件总数 > 35

---

## 五、轮转算法

### 5.1 轻量检查（每次写入后必做）
1. 枚举 `.skills-memory/` 下 `YYYY-MM-DD.md`（排除 `archive/` 与 `MEMORY.md`）
2. 检查条件 A / B
3. 都不满足 → 输出「记忆轮转：无需归档」，结束

### 5.2 完整轮转
1. 列出全部日报按日期升序
2. 计算应归档集合：优先取日期 < 今天 − 30 天；若仅条件 B，取最早 K 篇使剩余 ≤ 30
3. 按年-月分组
4. 每组：读每篇提取摘要（1-2 行场景/产出 + 1 行关键决策）→ 建/写 `archive/YYYY-MM.md`（幂等去重：已有该日期节则跳过）→ 提取可复用决策去重追加至 `MEMORY.md` → 更新 archive 摘要计数
5. 删除已成功写入 archive 的原日报
6. 检查 MEMORY.md 行数：超 500 → 旧条目入 `## 历史存档`；`## 历史存档` 超 200 → 迁 `archive/legacy-memory-{YYYY}.md`

### 5.3 校验
- archive 存在且含每日摘要 / MEMORY.md 已追加无重复 / 原日报已删 / 剩余 ≤ 30 / 归档动作已记入今日日志

---

## 六、首次运行安全开关

- `archive/` 不存在或为空（首次轮转）→ 暂停向用户确认后再删原文
- 后续自动执行

## 七、月度归档文件模板

```markdown
# 记忆归档 - {YYYY-MM}

> 由记忆轮转机制于 {归档执行日期} 生成。
> 来源：{YYYY-MM} 月共 {N} 篇日报（原文件已删除）。
> 可复用决策已同步至 ../MEMORY.md；本文件仅保留每日摘要。

## 归档摘要
- 归档日报数：{N}
- 时间范围：{最早日期} ~ {最晚日期}
- 提取至 MEMORY.md 条目数：{M}

## 每日摘要

### {YYYY-MM-DD}
- 场景/产出：{1-2 行}
- 关键决策：{1 行}
```

---

## 八、Step 0 记忆加载

1. 必读：`MEMORY.md` 正文区（`## 历史存档` 之前）
2. 必读：今日 `YYYY-MM-DD.md`（如存在）
3. 按需：最近 1 个月度归档 `archive/YYYY-MM.md`（延续项目时回读）
4. 必读（延续项目）：`project-tracker.md` 对应项目段，定位上次中断的 Phase
5. 不读：`## 历史存档` 与 `archive/legacy-memory-*.md`（除非用户明确要求找旧决策）

---

## 九、本技能特有记忆（并入通用 .skills-memory 的约定）

执行 mvp-expert-team 全流程时，除通用日志外，以下项目内产物按规范落盘（放在项目目录而非 .skills-memory，属交付物的一部分）：
- `docs/decisions/OPEN-DECISIONS.md`：悬而未决登记册（决策待外部条件/待评估/既有边界），每 Phase 开始复现尝试关闭，关闭可升格 ADR
- `项目/.workbuddy/memory/pitfalls.jsonl`（或项目内 `.skills-memory` 旁同等位置）：踩坑自学习（稳定签名去路径行号版本号；按技术栈指纹交集召回注入）
- 每次 Phase 开始把未决项自动复现到工作上下文最前面（「N 未决 + M 已决」汇总）

> 增量增删纪律：经验文件禁止整篇重写，一条「在 X 情形下因为 Y 会踩 Z，应当 W」远胜「要注意质量」。
