## 使用说明（本技能首次使用必读）

**这是 mvp-expert-team 技能的长期记忆文件**，结构如下：

| 分段 | 用途 | 写入时机 |
|------|------|----------|
| `## mvp-expert-team` | 技能产生的可复用经验（选型教训、踩坑、用户偏好修正） | 每次调用完成后 |
| `## 用户偏好` | 跨项目可复用的用户偏好（确认节奏、交付格式、模板选择） | 用户表达偏好后 |

**写入纪律**：
1. 每条 1-2 行，禁止长段（>3 行 = 应该写到 references/04 当方法论，而非记忆）
2. 写入前先查同分段是否已有语义相近条目，有则更新而非追加（去重）
3. 一条好记忆格式：「在 X 情形下因为 Y 会踩 Z，应当 W」（例：移动端用 h-screen 因地址栏高度导致内容被截断 → 用 min-h-[100dvh]）
4. 不写一次性事件（如某次项目用了哪个图标库）——进 project-tracker.md
5. 不写可推导的事实（如"Spec 需要 12 章"）——那是规则文档的内容

**示例条目**（首次使用时可参考结构，真实条目由后续调用沉淀）：
```
## mvp-expert-team

- 移动端 Hero 视口：h-screen 被地址栏截断 → 用 min-h-[100dvh]（指纹 css-100dvh）
- Taro 3 小程序云函数：CloudBase 必须先开通静态托管才能用 → Spec 锁定时检查
- 用户对反 AI 味敏感度高 → 19 项视觉清单在 Phase 2 设计门禁必跑

## 用户偏好

- 三文档确认后默认自动推进，不每步都问
- 部署平台优先选国内（CloudBase/阿里云）除非用户明确要求海外
```
