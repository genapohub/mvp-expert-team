## 1. PRD 模板（PM · Phase 1 产出）

```markdown
# PRD - {项目名} v{版本}

## 问题陈述
谁在什么场景下遇到了什么痛点？现在怎么解决的？为什么不行？
（不是功能清单，是问题。用户说"我要打卡工具"→ 挖"考勤管理还是习惯养成"）

## 目标用户
- 主要用户画像（年龄/职业/场景/技术水平）
- 次要用户画像

## 竞品分析
| 竞品 | 核心功能 | 优势 | 劣势（来自差评） | 定价 |
|------|----------|------|------------------|------|
| ...  | ...      | ...  | ...              | ...  |

## 我们的差异化
用户为什么选我们而不是竞品？（不许写"更好用""更全面"这种空话）

## 核心功能（RICE 排序）
| 功能 | Reach | Impact | Confidence | Effort | Score | MVP? |
|------|-------|--------|------------|--------|-------|------|
| ...  | ...   | ...    | ...        | ...    | ...   | ...  |

RICE = (Reach × Impact × Confidence) / Effort
- Reach 1-10（每季度受影响用户数）；Impact 0.25/0.5/1/2/3；Confidence 50%/80%/100%；Effort 1-10 人月

## MVP 范围
仅保留 RICE 最高 1-3 个功能，其余进 Backlog（明确列出被砍的）

## 验收标准（Given/When/Then 或 EARS）
- Given [前提], When [操作], Then [可观察结果]

## 边界条件
空状态 / 错误状态 / 加载状态 / 边界值 / 并发 / 离线 / 权限拒绝

## 非功能需求
| 类别 | 要求 | 优先级 |
|------|------|--------|
| 性能 | 首屏 < 3s，API p95 < 500ms | P0 |
| 可用性 | 无单点故障，核心流程降级可用 | P1 |
| 安全 | HTTPS + JWT + 输入校验 + 速率限制 | P0 |
| 兼容性 | Chrome/Safari/Firefox 最新 2 版，微信最新版 | P0 |
| 可访问性 | WCAG 2.1 AA 基本合规 | P2 |
| 国际化 | 如有海外用户预留 i18n | P2 |
| 数据埋点 | 注册/激活/留存/付费转化全埋 | P1 |

## 埋点方案（MVP 必埋，不埋 = 上线无法验证假设）
| 类别 | 必埋事件 | 说明 |
|------|----------|------|
| 获客 | page_view, sign_up_complete | 注册转化率 |
| 激活 | first_core_action | 第一个核心操作 |
| 留存 | session_start, session_duration | DAU/MAU |
| 转化 | upgrade_click, payment_complete | 付费漏斗 |
| 异常 | error_occurred | 前后端错误 |
```
埋点实现：轻量 SDK（Mixpanel/Umami/自建 trackEvent 封装）；事件命名 `{对象}_{动作}`；属性带 user_id/timestamp/device/version；不采集 IP 与原始输入。

## 3. OpenAPI 片段（架构师 · 机器可读契约）

```yaml
openapi: 3.0.3
info:
  title: {项目名} API
  version: 1.0.0
paths:
  /api/v1/auth/register:
    post:
      summary: 用户注册
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/RegisterRequest'
      responses:
        '201':
          description: 注册成功
components:
  schemas:
    RegisterRequest:
      type: object
      required: [email, password, name]
      properties:
        email: { type: string, format: email }
        password: { type: string, minLength: 8 }
        name: { type: string }
```

API 命名规范：版本号在路径 `/api/v1/`；统一响应 `{ "code": 0, "data": {}, "message": "" }`（code=0 成功）；分页响应 `{ items, total, page, limit, hasMore }`；RESTful 动词 + 资源复数。

## 5. 设计系统交付物模板（设计师 · Phase 2 产出）

### DESIGN.md 9 节
```markdown
# {产品名} 设计规范

## 1. Visual Theme & Atmosphere
- 视觉主题关键词（3-5 个，要具体："温暖且机械"而非"现代优雅"）
- 氛围描述

## 2. Color Palette & Roles
- A1-identity 色（--bg, --surface, --fg, --muted, --accent, --border）
- A2 语义色（--success, --warn, --danger）
- B-slot 别名（--fg-2, --surface-warm, --meta）
- 每屏强调色使用 ≤2 处说明

## 3. Typography Rules
- 字体栈（--font-display, --font-body, --font-mono）
- 字号层级（12/14/16/18/20/24/32/40px）
- 字距（正文 0；小字 0.01-0.02em；ALL CAPS ≥0.06em；标题 ≥32px -0.01~-0.02em）
- 字重（400 正文 / 510 强调 / 590 标题）

## 4. Component Stylings
- 按钮（Primary/Secondary/Ghost/Pill）+ 圆角 + 内边距
- 卡片（1px 边框 + 中等圆角 + 无默认阴影）
- 输入框（焦点环 + 验证状态）

## 5. Layout Principles
- 栅格（桌面 12 / 平板 8 / 手机 4 列）
- 节区节奏（桌面 80 / 平板 48 / 手机 32px）
- 容器最大宽度（1080-1200px）

## 6. Depth & Elevation
- 三级层级（--elev-flat / --elev-ring / --elev-raised）
- 深色模式用亮度递进代替阴影

## 7. Do's and Don'ts
- 允许的设计模式 / 禁止的设计模式（7 大罪）

## 8. Responsive Behavior
- 断点（<640 / 640-1024 / 1024-1280 / >1280）
- 导航（移动底部 TabBar / 桌面左侧 Sidebar）
- 触摸目标 ≥44×44px

## 9. Agent Guide
- 给前端/下一位执行者的实现提示
```

## 7. 交付包结构（运维 · Phase 4 产出）

```
delivery/
├── README.md             # 项目说明 + 一键启动命令
├── docker-compose.yml    # 或 cloudbaserc.json（部署平台以 Spec 锁定为准）
├── .env.example          # 环境变量模板（.env 永不提交）
├── .gitignore            # 忽略 node_modules/.env/dist 等
├── DEPLOY.md             # 部署步骤 + 回滚方案
├── TEST_REPORT.md        # QA 质量报告
└── USER_GUIDE.md         # 基本操作说明
```

交付标准：用户拿到后 1）复制 .env.example 为 .env 填密钥 2）执行 `docker compose up -d` 或对应部署命令 3）访问链接开始使用。不含 node_modules/.env/dist/日志/IDE 配置。

## 8. 其他可填空小件

### OPEN-DECISIONS 登记册行
```markdown
| Date | Source | Open Item | Related Constraints | Current Leaning | Blocked By | Resolves When | Status |
|------|--------|-----------|---------------------|-----------------|------------|---------------|--------|
| {日期} | Phase {N} | {未决事项} | {约束} | {倾向} | {阻塞方} | {何时可解} | OPEN |
```
固定 slug：`waiting-on-external-condition`（等用户/第三方）/ `design-decision-to-evaluate`（待 POC）/ `existing-design-boundary`（既有边界）。只追加 + 就地关闭（补 Resolution）。

### pitfalls.jsonl 踩坑条目
```json
{"signature": "dependency/module-not-found/react-router-dom", "family": "dependency", "first_seen": "2026-09-06T10:00:00Z", "episode_count": 1, "stack_fingerprint": ["react-router-dom@6.21.0"], "root_cause": "...", "fix": "...", "validated": false}
```
同一签名只追加 episode 计数，不重复落条；300 条上限最久未命中淘汰。

### 决策日志行
```
[{时间}] Phase {N} - {决策描述} - {原因} - {影响}
```

verdict: pass | fail
