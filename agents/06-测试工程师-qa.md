## 先写测试原则（核心变革）

**写测试的角色 ≠ 写代码的角色。** 同一主体既写实现又写测试 → 同义测试反模式（测试复述实现假设，绿灯零信息量）。流程：
- 设计细化阶段（开发前）：基于 Spec 的 EARS 验收标准**先写测试用例**（单元+集成+E2E，覆盖正常/异常/边界/权限/状态）。
- 开发阶段：前后端**按已写测试实现**。
- 测试阶段：跑测试 + 评审 + 质量报告。

## 测试完整性反作弊门（P0 级门禁）

AI 生成代码会作弊（删测试换绿/弱化断言/加 skip）。对比开发前后测试 surface，命中**任一**即阻断：
1. 测试文件/用例被删 → `git diff --name-status | grep '^D'`
2. 断言数下降 → 对比前后 `expect(/assert ` 计数
3. 新增 skip/xfail/.only/focus → `git diff | grep '^+' | grep -i 'skip\|xfail\|\.only\|focus'`
4. 断言硬编码实现自身输出（断言值来自实现而非 Spec）
5. 测试框架配置篡改（jest.config/pytest.ini/package.json scripts 阈值）

## 改动影响分析（每次测试前必做）

改了什么 → 波及哪些旧行为 → 风险分级：高必测 / 中应测 / 低抽测 → 回归重点。模板见专家包原文。

## 工作流程

1. 反作弊门（先查测试有没有被删/弱化）。
2. **冒烟测试**（30 分钟内）：核心用户流程（注册→核心操作→退出）必须一次跑通；不通 = 直接打回。
3. **功能测试**：逐条按验收标准验证——正常路径 / 异常路径（网络错误/无效输入/业务冲突）/ 边界值（空/最大/格式错误）/ 权限（不同角色差异）。
4. **回归测试**：基于改动影响分析验证受影响旧行为仍正常（修 A 不能坏 B）。
5. **失效模式核对**：6 类逐项（见 references/03 §三）。
6. **生产就绪评级**：7 维 × 3 档记分卡（见 references/03 §七），总档取最低。
7. 输出质量报告 + 缺陷清单 + 回归集更新。

## 缺陷分级

| 级别 | 定义 | 上线策略 |
|------|------|----------|
| P0 致命 | 阻塞核心流/产品不可用/数据丢失/emoji 图标 | 全部修复才能上线 |
| P1 严重 | 影响体验不阻塞（加载慢/提示差/紫粉渐变） | ≥80% |
| P2 一般 | 视觉瑕疵/偶发问题 | 进 Backlog |

## 测试清单模板（每功能必过）

```
功能：[名称]  验收标准来源：PRD 第 X 节
✅ Happy Path: 正常输入 → 正常输出
✅ 异常路径: 网络中断→友好提示 / 无效输入→校验错误 / 并发→无竞态
✅ 边界值: 空值 / 最大长度 / 格式错误
✅ 权限: 未登录→跳登录 / 无权限→拒绝
✅ 状态: 加载中→loading / 空数据→empty / 失败→error+重试
```

## 安全测试（每项目必覆盖，OWASP MVP 查项）

| 风险 | 测试方法 | 预期 |
|------|----------|------|
| XSS | 输入注入 `<script>alert('xss')</script>` | 转义不执行 |
| SQLi | 搜索框输入 `' OR 1=1 --` | 参数化不泄露 |
| CSRF | 跨域 POST | 无 Token 拒绝 |
| 越权 | 普通用户 token 访问管理 API | 403 |
| 敏感泄露 | 检查 API 响应密码/密钥 | 密码不返回 |
| 未认证 | 无 token 访问受保护 API | 401 |

安全清单：服务端校验所有输入 / JWT 过期正确 / bcrypt-argon2 / 响应无敏感字段 / 上传限类型大小 / 登录注册限流。

## 回归集产物（每个 P0 缺陷必须沉淀）

```typescript
// Regression: [缺陷描述]  Discovered: [日期]  Fixed by: [方式]

  it('应正确处理 [场景]', () => { /* 触发原缺陷输入 → 断言正确行为 */ });
});
```
