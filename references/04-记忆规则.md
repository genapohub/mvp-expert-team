# 记忆轮转归档规则（mvp-expert-team 专用）

> 本文件定义 mvp-expert-team 的记忆生命周期管理算法。
> **记忆目录 = 技能根目录下的 `memory/`**（与 SKILL.md 同级，随技能携带），每次调用先读后写，无外部依赖。

## 零、记忆目录定位（所有工具统一规则）

`memory/` 位于**技能根目录**（SKILL.md 所在目录）下，不是交付项目目录、不是用户工作目录。

**Step 0.1 定位技能根**
- 无论技能被 WorkBuddy / Codex / Cursor / ZCode / Trae 哪个工具加载，`memory/` 都以**当前 SKILL.md 所在目录**为根。
- 相对写法：`{技能根}/memory/MEMORY.md`、`{技能根}/memory/YYYY-MM-DD.md`。
- 判断方法：SKILL.md 的加载路径的父目录即技能根（如 `~/.workbuddy/skills/mvp-expert-team/`）。

**Step 0.2 验证与自建**
- `memory/README.md` 由技能仓库内置（clone 即存在）；`MEMORY.md`/`project-tracker.md`/`archive/` 为运行期文件。
- 若 `MEMORY.md` 等缺失（旧副本/手工精简），执行 `mkdir -p {技能根}/memory/archive` 并写入初始骨架（MEMORY.md 分段头 / project-tracker.md 格式头）。
- 创建失败 → 报错并告知用户手动创建，不得静默跳过。

---

## 一、目录结构

```
{技能根}/memory/
├── README.md              # 目录说明（技能仓库内置）
├── MEMORY.md              # 长期记忆：可复用决策、项目约定（按 ## 技能名 分段）
├── project-tracker.md     # 项目进度台账（ledger）：任务进度/阶段里程碑/关键裁决 Ruling
├── YYYY-MM-DD.md          # 活跃日志：每次调用当天记录（追加模式）
└── archive/               # 冷归档
    └── YYYY-MM.md         # 月度日报摘要（12 篇/年）
```

> **project-tracker.md 说明**：
> - MEMORY.md 存**可复用决策**，project-tracker.md 存**进行中项目的任务级进度**，两者解耦。
> - 由项目总监维护（多 Phase 交付时更新）；角色不写本文件。
> - 会话中断后，下次调用先读 project-tracker.md 恢复项目状态再定位中断位置。
> - 格式：`## {项目名}（日期 → 状态）` 段下追加 `[日期] Phase/角色 完成：摘要`、`[日期] 裁决（Ruling）：决定—理由—代价`、`[日期] 阻塞：问题+状态`。
> - 不参与 30 天归档，随项目生命周期保留；项目结束后段首标注 `[已结项]`。

---

## 二、每次调用必做的「先读后写」

| 时机 | 动作 | 读/写 |
|------|------|-------|
| 调用前 | 读 `MEMORY.md` + 今日日志 + `project-tracker.md`（延续项目定位中断点；全新请求仅确认无延续） | 读 |
| 调用中 | 每 Phase 完成后追加今日日志条目；关键裁决入 project-tracker.md | 写 |
| 调用后 | 可复用经验去重写 MEMORY.md；执行轮转检查 | 写 |

### 每日日志（YYYY-MM-DD.md）

每条格式：`[mvp-expert-team] 场景描述 → 关键决策`

- 一行一个条目；同一天多条按 Phase 分组。
- 多 Phase 交付：每 Phase 各一条，最后追加交付汇总条目。
- 单 Phase 咨询（只用技能一部分能力）也须记一条。

### 长期记忆（MEMORY.md）

- 按 `## mvp-expert-team` 分段（也可按主题建 `## 用户偏好` 等分段）。
- 每条 1-2 行；写入前检查同分段是否已有语义相近条目，有则更新而非追加（去重）。

---

## 三、轮转参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 年龄阈值 | 30 天 | 日报超此年龄 → 触发归档 |
| 数量硬上限 | 35 篇 | 防止阈值长期不触发导致的堆积 |
| 归档粒度 | 月度 `archive/YYYY-MM.md` | 保留每日 1-3 行摘要，压缩约 95% |
| MEMORY.md 自清理 | 超 500 行 | 超 6 个月未更新的条目移至 `## 历史存档` 尾段 |
| 历史存档溢出 | `## 历史存档` 超 200 行 | 整体迁移到 `archive/legacy-memory-{YYYY}.md` |

---

## 四、触发条件

每次写入日志后轻量检查，满足任一即触发完整轮转：
- 条件 A：存在日报日期早于「今天 − 30 天」
- 条件 B：日报文件总数 > 35

---

## 五、轮转算法

### 5.1 轻量检查（每次写入后必做）
1. 枚举 `memory/` 下 `YYYY-MM-DD.md`（排除 `README.md` / `MEMORY.md` / `project-tracker.md` / `archive/`）
2. 检查条件 A / B
3. 都不满足 → 输出「记忆轮转：无需归档」，结束

### 5.2 完整轮转
1. 列出全部日报按日期升序
2. 计算应归档集合：优先取日期 < 今天 − 30 天；若仅条件 B，取最早 K 篇使剩余 ≤ 30
3. 按年-月分组
4. 每组：读每篇提取摘要（1-2 行场景/产出 + 1 行关键决策）→ 建/写 `archive/YYYY-MM.md`（幂等去重：已有该日期节则跳过）→ 提取可复用决策去重追加至 `MEMORY.md` → 更新 archive 摘要计数
5. 删除已成功写入 archive 的原日报
6. 检查 MEMORY.md 行数：超 500 → 旧条目入 `## 历史存档`；`## 历史存档` 超 200 → 迁 `archive/legacy-memory-{YYYY}.md`

### 5.3 校验
- archive 存在且含每日摘要 / MEMORY.md 已追加无重复 / 原日报已删 / 剩余 ≤ 30 / 归档动作已记入今日日志

---

## 六、首次运行安全开关

- `archive/` 为空（首次轮转）→ 暂停向用户确认后再删原文
- 后续自动执行

## 七、月度归档文件模板

```markdown
# 记忆归档 - {YYYY-MM}

> 由记忆轮转机制于 {归档执行日期} 生成。
> 来源：{YYYY-MM} 月共 {N} 篇日报（原文件已删除）。
> 可复用决策已同步至 ../MEMORY.md；本文件仅保留每日摘要。

## 归档摘要
- 归档日报数：{N}
- 时间范围：{最早日期} ~ {最晚日期}
- 提取至 MEMORY.md 条目数：{M}

## 每日摘要

### {YYYY-MM-DD}
- 场景/产出：{1-2 行}
- 关键决策：{1 行}
```

---

## 八、Step 0 记忆加载

1. 必读：`MEMORY.md` 正文区（`## 历史存档` 之前）
2. 必读：今日 `YYYY-MM-DD.md`（如存在）
3. 按需：最近 1 个月度归档 `archive/YYYY-MM.md`（延续项目时回读）
4. 必读（延续项目）：`project-tracker.md` 对应项目段，定位上次中断的 Phase
5. 不读：`## 历史存档` 与 `archive/legacy-memory-*.md`（除非用户明确要求找旧决策）

---

## 九、与项目交付物的分工

`memory/` 只存**技能运行记忆**（决策/经验/进度）。交付物本体（Spec/代码/测试报告/DESIGN.md 等）产出到**用户指定项目目录**，不进 memory/。以下项目内决策文档也产出到项目目录（属交付物一部分，非记忆）：
- `docs/decisions/OPEN-DECISIONS.md`：项目内悬而未决登记册，每 Phase 开始复现尝试关闭，关闭可升格 ADR
- 项目级 `pitfalls.jsonl`：踩坑自学习（如项目有独立记忆需求时）

> 增量增删纪律：记忆文件禁止整篇重写，一条「在 X 情形下因为 Y 会踩 Z，应当 W」远胜「要注意质量」。
